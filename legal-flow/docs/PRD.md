# «Правовой Поток» — PRD (спецификация MVP)

Сайт: https://pravpotok.ru (закрытое тестирование). Выпускной проект курса.

## 1. Коротко
Редакционный сервис для юристов и редакций юридических изданий: сам следит за правовыми сайтами, находит значимые
новости, готовит самостоятельный черновик по официальному документу, а решение о публикации оставляет человеку.
Результат — проверенные материалы, готовые к выгрузке в XML или по API.

## 2. Проблема
- Правовых новостей много (Гарант, Право.ру, КонсультантПлюс и др.): ручной мониторинг отнимает часы каждый день.
- Копировать чужой текст нельзя: нужен самостоятельный материал со ссылкой на официальный первоисточник.
- Ошибка в реквизите или факте дорого стоит доверием клиентов, поэтому полностью автоматическая публикация
  недопустима — нужен контроль юриста.

## 3. Целевая аудитория
| Сегмент | Что им нужно |
|---|---|
| Юридические фирмы и практикующие юристы | Новости для клиентов, блога и рассылок без ежедневной рутины |
| Редакции юридических изданий и порталов | Единая очередь тем, редакторский контроль, выгрузка в XML/API |
| Юристы-блогеры, маркетологи юркомпаний | Свежие поводы для публикаций с проверенными реквизитами |

## 4. Ценность
Экономия времени на поиске и подготовке при сохранении контроля: источник темы остаётся внутри редакции, в публикацию
попадает самостоятельный текст и официальный документ; для каждого черновика виден процент совпадения с оригиналом.

## 5. Основной сценарий
Кто: юрист или редактор. Что вводит: сайты-источники, тему, ключевые слова и стоп-слова, расписание. Что получает:
очередь материалов с черновиками, проверенными фактами и выгрузку утверждённых материалов.

1. **Лендинг** → «Запросить ранний доступ» (заявка) или «Посмотреть пример без регистрации».
2. **Вход** администратором (в закрытом режиме) → **настройка потока**: сайты, тема, ключевые слова, расписание.
3. **Сбор**: система проверяет robots.txt, находит ленту, собирает новые материалы, ИИ готовит черновики автоматически.
4. **Работа с материалом**: вкладки «Текст для публикации», «Источник» (оригинал и процент совпадения), официальный
   документ (необязательно), паспорт фактов → проверка редактором → утверждение → публикация.
5. **Экспорт**: XML-файл (последние N или выбранные вручную) или API по ключу.

## 7. Нефункциональные требования и ограничения
- Свой сервер (VPS), HTTPS, ночные резервные копии базы; пароли — Argon2id; ключи ИИ — шифрованные.
- Публикации нет без решения человека; сайт-источник не попадает в XML и публичный текст.
- Сбор уважает robots.txt; для нового сайта нужно подтвердить право использовать его материалы.
- Зависимость от внешнего ИИ: фильтр YandexGPT может отказать на чувствительной теме → запасная модель.
- Скорость сбора ограничена вежливым опросом сайтов; платежи и почтовые уведомления не подключены.

## 8. Проверка гипотезы
**Гипотеза:** юристам и редакциям нужен сервис, который готовит самостоятельные материалы из правовых новостей
под контролем юриста, и они готовы оставить контакты ради раннего доступа.
**Как проверяем:** лендинг с кнопкой «Запросить ранний доступ» и формой заявки; воронка из уникальных посетителей:
просмотр → нажатие кнопки → открытие формы → заявка (вкладка «Заявки» в админке). Дополнительный сигнал — открытие
примера без регистрации. Сравнение «исходник и переписанная статья» встроено в сам продукт (счётчик совпадения).
**Критерий успеха (целевой порог):** конверсия посетителя лендинга в заявку ≥ 5% и не менее 10 заявок от целевой
аудитории за две недели рассылки/публикаций. Если порог не достигнут — пересматриваем формулировку ценности и аудиторию.

## 9. Риски
| Риск | Мера |
|---|---|
| ИИ придумывает факт или реквизит | Паспорт фактов, проверка юриста, автоматической публикации нет |
| Слишком близкий к оригиналу текст | Счётчик совпадения и предупреждение, переписывание вручную |
| Сайт запретил сбор или поменял вёрстку | robots.txt соблюдается, сбор останавливается; разборщики общие (RSS/sitemap/эвристики) |
| Отказ или недоступность модели; истёк временный ключ | Запасная модель; замена ключа в админке без перезапуска |
| Потеря данных при сбое сервера | Ночные копии; копии нужно периодически скачивать на другой носитель |
| Низкий интерес аудитории | Проверка гипотезы заявками до развития платных функций |
| Персональные данные в заявках | Только необходимые поля, согласие, страница «Какие данные мы храним» |

# Руководство пользователя

## Что это за программа

Программа автоматически формирует ежемесячный отчёт о выполненных ремонтах
(HTML, PDF, DOCX) на основе одного файла-выгрузки из вашей учётной системы —
без ручного пересчёта в Excel.

## Как запустить программу

**Если у вас уже есть файл `RepairReportApp.exe`** (обычный случай для
пользователя, не разработчика):

1. Скопируйте `RepairReportApp.exe` на компьютер с Windows 10/11 — устанавливать
   Python или что-либо ещё не нужно, файл самодостаточен.
2. Дважды кликните по файлу — откроется окно программы. Первый запуск может
   занять на несколько секунд дольше обычного (программа распаковывает себя
   во временную папку) — это нормально.
3. Если антивирус или SmartScreen предупреждают о незнакомом файле — это
   типичная реакция на новый, ещё не «репутационный» .exe, а не признак
   проблемы; разрешите запуск («Подробнее» → «Выполнить в любом случае»).
4. Дальше — по шагам в разделе [«Шаги работы»](#шаги-работы) ниже.

**Если у вас есть исходный код программы** (для разработчика/тестирования):

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Откроется то же самое окно — просто без сборки в отдельный .exe. Как собрать
сам `.exe` из исходного кода — см. `packaging/BUILD.md`.

## Какой файл загружать

Загружайте **весь накопительный файл выгрузки** (`WR_Consolidated_List_*.xlsx`),
а не файл только за нужный месяц — и не какой-либо другой промежуточный или
сводный файл. Так работает программа с любым месяцем каждый раз.

**Почему именно весь накопительный файл, а не только новый месяц:**
колонки «Предыдущий период» и «Динамика» программа считает, сравнивая два
месяца из ЭТОГО ЖЕ файла (текущий и календарно предшествующий) — отдельной
базы истории программа не ведёт. Если приложить только один месяц, сравнение
будет недоступно, и программа честно об этом сообщит, а не покажет неверные
цифры.

## Как программа определяет период

Программа сама находит все месяцы, присутствующие в файле (по колонке
«Дата акта»), и по умолчанию выбирает последний (самый новый). Вы можете
выбрать другой месяц из списка, чтобы пересчитать отчёт задним числом —
программа заново найдёт для него предыдущий месяц в том же файле.

Если календарно предыдущий месяц отсутствует в файле — программа явно
покажет предупреждение «Календарно предыдущий месяц отсутствует в файле —
сравнение недоступно» вместо того, чтобы молча сравнить с более старым
периодом или показать пустые/неверные значения.

## Профиль заказчика

Реквизиты шапки отчёта (Исполнитель, Заказчик, номер и дата договора,
подписант) не хранятся в файле выгрузки — их нужно один раз занести в
профиль заказчика (кнопка «Новый / Редактировать…»). В следующие месяцы
просто выбирайте сохранённый профиль из списка.

## Три окна загрузки

Программа показывает три равноценных, независимых окна для перетаскивания
файлов — рядом друг с другом:

1. **Выгрузка ремонтов** (`WR_Consolidated_List_*.xlsx`) — основной файл,
   без него отчёт не построить.
2. **Выгрузка по запасным частям** — для раздела 10, необязательный.
3. **Выгрузка по технической поддержке** — для раздела 11, необязательный.

Все три файла загружаются независимо и в любом порядке — перетащите
столько файлов, сколько у вас есть, и нажмите «Сформировать отчёт». Никаких
галочек «показывать раздел» в интерфейсе нет: если файл для раздела 10
и/или 11 загружен — этот раздел автоматически появится в отчёте с реальными
цифрами; если файл не загружен — раздел просто не появится в отчёте,
остальная часть отчёта формируется как обычно. Загрузив все три файла, вы
получаете отчёт в полном составе — все 12 разделов с реальными данными.

## Раздел 10 — запасные части

Раздел 10 («Аналитика поставок запасных частей») строится из выгрузки по
запасным частям из логистической/учётной системы (второе окно загрузки).

Формула раздела подтверждена точно: программа берёт из файла запчастей
строки за ДВА месяца — выбранный текущий период и календарно предыдущий
(так же, как остальные разделы отчёта сравнивают «текущий/предыдущий»),
считает по дате отправки заказа. Если в загруженном файле запчастей нет
данных за нужные два месяца — раздел покажет предупреждение об этом, а не
нулевые/неверные цифры.

Раздел 10.2 «География поставок» определяет город/округ приближённо, по
тексту адреса доставки — для большинства городов совпадает с эталоном
точно, но для отдельных нестандартных адресов возможны небольшие
расхождения.

## Раздел 11 — техническая поддержка

Раздел 11 («Аналитика технической поддержки») строится из выгрузки по
обращениям в техподдержку (третье окно загрузки). Формула подтверждена
точно по эталонному отчёту: количество заявок, топ-15 сервисных центров по
объёму обращений, распределение по темам обращений и аудит заполнения
заявок (11.1, 11.3, 11.4) — всё считается по дате создания заявки, за
выбранный период и календарно предыдущий месяц вместе.

Подраздел 11.2 «Инженеры поддержки» в отчёте всегда остаётся без таблицы —
это не ошибка программы: поле «Кто ответил» пустое во всей выгрузке, и в
эталонном отчёте по той же причине под этим заголовком тоже нет таблицы.

Обратите внимание: доля закрытых заявок в разделе 11 (как и статусы в
разделе 10) зависит от того, НАСКОЛЬКО СВЕЖАЯ у вас выгрузка — статус
заявки меняется со временем, поэтому при выгрузке через месяц после
отчётного периода доля закрытых заявок будет выше, чем была на момент
формирования отчёта изначально. Это ожидаемое поведение для живых данных,
а не ошибка расчёта — количество заявок и остальные показатели, не
зависящие от статуса, от этого не меняются.

## Шаги работы

1. Перетащите файл `WR_Consolidated_List_*.xlsx` в первое окно (или
   нажмите «Выбрать файл…»).
2. Перетащите файл по запасным частям во второе окно, если хотите видеть
   раздел 10 — тогда в отчёте появятся реальные данные по нему.
3. Перетащите файл по технической поддержке в третье окно, если хотите
   видеть раздел 11.
4. Дождитесь, пока программа определит период — в выпадающем списке
   появится список найденных месяцев, по умолчанию выбран последний.
5. Выберите (или создайте) профиль заказчика.
6. Отметьте нужные форматы выгрузки (можно несколько сразу): HTML, PDF, DOCX.
7. Нажмите «Сформировать отчёт» и укажите папку для сохранения.

## Логи

Если что-то пошло не так, журнал работы программы сохраняется в
`%LOCALAPPDATA%\RepairReportApp\logs\app.log` — приложите этот файл при
обращении к разработчику.
